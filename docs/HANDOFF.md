## How we work
- **One task, one worktree:** `git worktree add -b task/NN-name ../caravela-wt/task-NN main`. Write the brief at `docs/tasks/NN-*.md` inside that worktree.
- **Start the agent in a herdr pane** (check `HERDR_ENV=1`; your own pane is `$HERDR_PANE_ID`, e.g. `w4:p1`):
  - `herdr pane split $HERDR_PANE_ID --direction right --cwd <worktree> --no-focus` (prints JSON; the new id is at `.result.pane.pane_id`).
  - `herdr agent start <name> --kind claude --pane <id> -- "Read docs/tasks/NN-*.md and execute it end to end. The user already approved the approach for this task."`
    - It often returns `timed out waiting for agent startup` even though the agent started fine. Check with `herdr pane read <id> --source recent` before retrying; don't start it twice.
  - Wait with `herdr agent wait <pane> --until done --until idle --until blocked`, run in the background. **`--timeout` is in milliseconds**; leave it out to wait indefinitely.
  - Follow-up instructions to a running or idle agent: `herdr agent prompt <pane> "…"` (queued if it's busy).
  - Reading results: `herdr pane read` only returns the last screen. For the full final report, read the agent's transcript: the session id is in `herdr pane list` (`agent_session.value`), and the file is `~/.claude/projects/*task-NN*/<session id>.jsonl` (take the last assistant text blocks).
  - Don't move an agent's pane (`herdr pane move`) while it runs: the agent loses its name and running `agent wait`s fail with `agent_not_running`. Wait on the pane id afterwards. To change the layout, it's simpler to split the right way from the start (one pane on the left, agents stacked with `--direction down`).
  - After a follow-up prompt, `agent wait` can return at once with the previous turn's `done`; wait ~15 s before starting it, and check the pane if it returns immediately.
  - Text on the agent's `❯` input line after it finishes is usually Claude Code's prompt suggestion, not something the user sent.
  - An agent waiting on Quick Connect polls with background shells, so `herdr agent wait --until idle` returns while it is still waiting. The code may only be in a screenshot or scrolled off the pane: read the last assistant text in its transcript, and if it is missing, `herdr agent prompt` it to print the code as text.
- **Parallel work:** two independent tasks can run at once. Keep each brief's file scope separate.
  - When two parallel tasks share data shapes, commit the shared types to `main` first (task 7 did this in `src/components/types.ts`), so each brief can build against them without the other's files.
- **Device checks:** playback checks use the **Fire TV** (the user chose it in task 8; the simulator stalls playback 3–6 s in). UI-only checks can use the Vega simulator (details in Gotchas). Captions also need the TV.
- **Signing in during a check:** a fresh install wipes the session. Agents sign in as `demo` with an empty password (no user needed). Only if a check needs `melojms` (e.g. its library or resume points): Quick Connect; tell the agent to print the code on its own line as `QUICK CONNECT CODE: <code>`, keep polling, and fetch a new code if one expires. The orchestrating session relays the code to the user, who approves it in jellyfin-web. Never use `melojms`'s password.
- **Shared Fire TV** (`192.168.50.124:5555`): every install, launch, input or screenshot runs inside `flock /tmp/caravela-device.lock -c '…'`.
  - Never start a long-running process (e.g. `loggingctl log -f`) inside the lock: it inherits the lock and holds it forever. Start log capture outside `flock`, detached, and stop it by pid.
  - When agents run in parallel, hold the lock for a whole flow (install → navigate → screenshot), not per step. Otherwise agents interleave on the TV.
  - **Typing:** focus the TextInput (the keyboard opens), wait about 3 s, then `inputd-cli send_text <text>`. Check with a screenshot: a stray key press can add a letter in front. Press Back to close the keyboard.
  - **Search field** (since R3 the field has `showSoftInputOnFocus={false}`): focus it, press KEY_ENTER to open the keyboard, wait ~3 s, `send_text`. The keyboard opens on the `a` key: Down ×4 then Right reaches its **Search** key (submits and closes it); Down ×3 then Right ×5 reaches **Clear**. Screenshot before pressing Enter on a key.
- **Before merging to `main`:**
  - Rebase onto `main` and resolve `package.json`, `manifest.toml` and `jest.config.json` by taking both sides.
  - If `package-lock.json` conflicts, regenerate it with a clean `rm -rf node_modules package-lock.json && npm install`; otherwise keep it and run `npm ci`.
  - Run `npm run lint` and `npm test`, then `npm run build:release`.
  - Install and launch on the simulator: `vega run-app build/x86_64-release/caravela_x86_64.vpkg com.melojms.caravela.main -d VirtualDevice` (on the TV: `build/armv7-release/caravela_armv7.vpkg … -d 192.168.50.124:5555`).
  - `run-app` reinstalls the package, which **wipes the app's storage** (saved servers, users and tokens). To restart without losing them, e.g. to check auto-login: `vega device terminate-app -d <VirtualDevice or TV> -a com.melojms.caravela.main`, then `vega device launch-app` with the same options.

## Gotchas
- **Debug builds** load JavaScript from Metro (`npm start` plus port forwarding); without it the app starts blank. Use **Release** builds for checks on the TV.
- **Jest:** the Vega preset's stand-ins for BackHandler and Dimensions are wrong for RN 0.83. `test/setup.tsx` replaces them, and `test/jestSetup.js` sets up the API tests. Both are listed in `jest.config.json` `setupFiles`.
- **Manifest:** the build adds `[[needs.module]]` entries for each native package it uses. Keep them when merging.
- **Untracked files:** the Amazon Builder Tools create an untracked `CLAUDE.md` and `.claude/skills/` in the repo. Leave them uncommitted; `.gitignore` ignores everything under `.claude/` except the project's own `caravela-next` skill.
- **Metro resolves `.json` before `.ts`:** a `.ts` module must never share a base name with a JSON file next to it (`licenses.ts` + `licenses.json` crashed the Release app in R4c). Jest resolves `.ts` first, so the tests don't catch it.
- **Vega OS 1.2 native-stack pops send no `transitionEnd`** (pushes do), so code that must wait for a pop to settle uses a timer (`POP_SETTLE_MS` in `RootNavigator`). On OS 1.2, removing more than the top screen of a stack at once crashes the screens library: unwind one pop at a time.
- **Steering focus away from a TextInput:** `FocusManager.setNextFocus` is ignored when the source is a `TextInput` (R7-h, Fire TV); use the `nextFocusDown`/`nextFocus*` prop with the target's native tag instead (Vega's TextInput typings omit it; `PasswordScreen` passes it through a typed spread). `setNextFocus` from a `Pressable` works (`PosterGrid`, `PlayerOverlay`).
- **Vega CLI:** read `vega_cli_commands_reference.md` (Amazon Devices MCP) before using new Vega CLI commands.
- **Vega Virtual Device (simulator)** (the user's choice for checks since task 7): `vega virtual-device start`, then `vega run-app build/x86_64-release/caravela_x86_64.vpkg com.melojms.caravela.main -d VirtualDevice` (wipes storage). Shared: run each flow inside `flock /tmp/caravela-sim.lock -c '…'`.
  - **Input works** with vda serial `emulator-5554`: `vega exec vda -s emulator-5554 shell inputd-cli button_press KEY_DOWN` (and `send_text`). The old note that keys don't reach apps is wrong on SDK 0.24.
  - **Screenshots:** `gwsi-tool-screenshooter` is black here, and `grim` doesn't work on GNOME Wayland. Capture the simulator's XWayland window from the host with ImageMagick: `W=$(xwininfo -root -tree | grep '"vega-virtual-device" "vega-virtual-device"' | grep 'Vega Virtual Device' | awk '{print $1}'); import -window "$W" <scratchpad>/x.png`. Look `W` up each time; crop off the on-screen remote on the right.
  - **Full-size captures** (README screenshots): `vega virtual-device stop`, then `vega virtual-device start --display-res 1920,1080`, then `GDK_BACKEND=x11 python3 scripts/sim-window-resize.py "$W" 1920 1080`.
