## Approach (approved)
androidtv has Settings → About; we do the same: Settings gets an **About** button, About is its own screen (Settings isn't scrollable, so nothing goes inline).

- **App version at runtime:** `@amazon-devices/expo-application` (~3.0.0, the RN 0.83 build; Vega docs: https://developer.amazon.com/docs/vega-api/0.24/expo-app). Read that page (Amazon Devices MCP `read_document`) for the install and any manifest changes before adding it. `nativeApplicationVersion` and `nativeBuildVersion` must show what's installed: `npm run build:release` sets them from `manifest.toml` (0.1.1 → build 1001, see `scripts/build-release.sh`).
  - The build adds a `[[needs.module]]` entry to `manifest.toml` for the new native package; keep it and commit it.
  - If the values come back empty or wrong on the simulator, **stop and report** (with what you saw) instead of building a fallback; the agreed fallback is a constants file generated by `build-release.sh`, which is a separate change.
- `src/about/appInfo.ts`:
  - `SOURCE_URL = 'https://github.com/melojms/caravela'`, `PRIVACY_URL = 'https://melojms.github.io/caravela/privacy'` (the user chose this; the page itself is published later), `LICENSE_NAME = 'GPL-2.0-or-later'`.
  - `getAppVersion()` → `{version, build}` from expo-application, `undefined` fields when it returns null.
  - `useServerInfo()`: the current server's name and version from `getPublicSystemInfo` (see `src/api/serverDiscovery.ts` for the call and `getDisplayVersion`), as a TanStack query with the per-user keys used in `src/api/*` (see `src/api/queryClient.tsx`). While it loads or if it fails, fall back to the stored `session.server.name` / `session.server.version` (stale after a server upgrade, which is why we fetch). A 401 goes through the usual expiry path.
- `src/screens/AboutScreen.tsx`: `ScreenContainer title="About"` (no toolbar, like Settings), `testID="about-screen"`, styled with Settings' `label` / `body` / `title` styles (`src/theme`):
  - **Caravela**, "Version 0.1.1 (build 1001)"; "Version unknown" if expo-application gives nothing.
  - **Server:** "<name> · Jellyfin <version>" (`getDisplayVersion`); just the name if no version is known. No address (screenshots end up in the README).
  - "Unofficial client, not affiliated with the Jellyfin project."
  - "Licence: GPL-2.0-or-later" and "Source: https://github.com/melojms/caravela" as text (TV links aren't clickable; no QR codes, the user chose text only).
  - "Privacy policy: https://melojms.github.io/caravela/privacy".
  - A **Third-party licences** `FocusableButton` (`testID="about-licenses"`) that navigates to `Licenses`. That route is registered in R4c, so don't press it in the simulator check. It is the screen's only focusable item and takes focus on open.
  - UI text uses British "licence(s)"; code identifiers stay `license` (npm's spelling).
- `src/screens/SettingsScreen.tsx`: an **About** `FocusableButton` (`testID="settings-about"`) in its own row after the auto-login row (and its error), under a small "About" heading like "Account". It navigates to `About`.
- `src/navigation/RootNavigator.tsx`: register `About` next to `Settings`.
