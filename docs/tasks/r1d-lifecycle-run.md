## Why
Amazon runs these lifecycle tests on every media app submission (list in `docs/PUBLISHING.md`, "Lifecycle tests Amazon runs"). Expected for each one: no crash, no blank screen, no audio leaking onto the launcher, no A/V sync issues. R1-a, R1-b, R1-c, R5 and R6 were built for them, but the nine tests have never been run together on a clean Release build. Doing it now finds the fixes before the store run.

What earlier work already showed (details in `docs/HANDOFF.md`, Status: "R1-0 lifecycle probe", "Checks on `main` after R1-a / R1-b / R5 / R6", and Follow-ups):
- Home, another app and the screensaver send `background`. `PlayerScreen` then calls `goBack()` (R1-a), which releases the player and sends stopped. Relaunching warm lands on Details, and Resume continues. JS is suspended about 4 s after `background`.
- **The OS sometimes kills the app** right after the player is released in the background (`MRM killed pid …` from lcm, about 2 in 6 times). The next launch is then a cold start on Home. Record every time it happens.
- **HDMI unplug, TV input switch and TV off disconnect the display, and Vega kills the app** within about 10–120 ms, with no `background`. Expect the launcher when the display comes back, a cold start on Home, and Details → Resume at the last progress report (≤3 s old). That is not Amazon's "paused, resumes from the same position". Record exactly what happens. Whether it passes is the user's call, so don't try to fix it.
- A plain Alexa question doesn't change `AppState`. Vega holds the player (`audiofocuspaused`) and resumes it by itself (`audiofocusgranted`). Since R1-b there is no "Playback stopped" error.
- R5: on a Bluetooth headset connect or disconnect, Vega re-routes the sound itself (with its own re-seek about 1.8 s after a connect). This TV's HDMI offers PCM only, so `supportsDolby` stays false and no reload happens.

## The tests
Run each one with **direct play, then HLS**. Use the order below: it keeps the cold-start and reboot tests near the end. The **full 5 minutes** apply wherever Amazon says 5 minutes (the user's choice).

1. **Back to the launcher.** Play → Back until the launcher → relaunch. Expected: the app works normally (Home loads, playing again works).
2. **Home.** Play → background it (the launcher app, as in How we work) → ask the user: is any audio playing on the launcher? → warm relaunch. Expected: no audio; Details shows the new resume point; Resume continues from it.
3. **Another app.** Play → background it → ask the user to play something with sound in another app (YouTube or Prime Video, whatever is installed; you can launch it for them) → back to the launcher → relaunch Caravela → Resume. Expected: no audio overlap at any point.
4. **Screensaver.** Play, then pause with OK, then send no input. Note when the screensaver or Ambient starts, and wait at least 5 minutes in total. Ask the user: any audio over the screensaver? Then Back. Expected (Amazon): still paused, back in the app. Since the screensaver backgrounds the app, R1-a leaves the player, so Details is the likely result. Record what you see, and whether Resume continues at the paused position.
5. **Alexa.** Play → the user asks "Alexa, what's the weather?" → wait for the card to close. Expected: the video pauses, no audio overlap, and playback resumes by itself at the same position with no error. If Alexa hears only part of the question and opens voice search, that's a different case (it backgrounds the app). Record it, then retry.
6. **Bluetooth headset** (the user's headset; there's no soundbar). (a) The headset is connected before playback starts: play for 1 minute. (b) Playing on the TV speakers, the user connects the headset mid-play, then disconnects it again. Ask the user each time: does the sound come out of the right device, and is it in sync with the picture (lip sync, door slams)? Expected: audio routes correctly and stays in sync, with no error and no reload.
7. **HDMI unplug.** Play → the user unplugs the Fire TV's HDMI for **5 minutes** → replug. Expected (Amazon): paused, resumes from the same position. Expected (R1-0): the app was killed. Record what the screen shows on replug, whether a relaunch is cold, and how far the resume point is from where playback was when it was unplugged.
8. **TV input / TV off.** The same as 7, but the user switches the TV to another input, or turns the TV off, for **5 minutes** (do input with direct play and off with HLS, or both with each if the user is happy to). The TV may switch back by itself through HDMI-CEC; note it.
9. **Device restart.** Play → `vega device reboot -d 192.168.50.124:5555` (you do this; the user approved it). Wait until `vega device list` shows the TV again (`vega exec vda connect 192.168.50.124:5555` if it doesn't), then restart the log capture. Then relaunch. Expected: still signed in as `demo` on the test server, and Details → Resume continues from the last position.

After each test, take a screenshot of the result and check `/Sessions` on the server: no session left over from a player that's gone. Write the result into the table before moving on, so nothing is lost if the run stops.
